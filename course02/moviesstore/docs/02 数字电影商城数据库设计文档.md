## 二、全局设计原则

### 2.1 领域拆分

数据库按业务域拆分，避免“超级表”：

- 用户域（Account）
- 内容域（Content）
- 交易域（Order）
- 资金域（Wallet / Coin）
- 会员域（Membership）
- 下载与风控域（Download / Device）



### 2.2 主键策略

- 所有业务表使用 `BIGINT UNSIGNED AUTO_INCREMENT`
- 不使用 UUID 作为主键（便于索引与排序）



### 2.3 时间字段规范

所有核心表统一包含：

```text
created_at DATETIME
updated_at DATETIME
```

必要时包含：

```text
deleted_at DATETIME NULL   -- 软删除
```



### 2.4 金额与金币精度

- 金币使用 `BIGINT`（最小单位为 1）
- 不使用 FLOAT / DOUBLE
- 真实支付金额使用 `DECIMAL(10,2)`



### 2.5 一致性与幂等

- 充值、扣币、授权发放必须在事务中完成
- 所有支付回调必须支持幂等
- 数据库层通过 **唯一索引 + 事务** 保证一致性

## 四、核心 ER 关系

### 4.2 简单说明

- User 1—1 Wallet
- User 1—N UserLoginDevice
- User 1—N RechargeOrder
- User 1—N CoinTransaction
- User 1—N PurchaseOrder
- PurchaseOrder 1—N PurchaseOrderItem
- PurchaseOrderItem 1—1 PurchaseLicense
- User 1—N Membership
- Membership 1—N MembershipRenewal
- User + Movie + Device → DownloadToken



### 4.3 详细解释

#### 4.3.1 整体设计思路

这张 ER 图并不是“表的堆砌”，而是围绕 **四条业务主线**展开：

1. 用户与账户主线
2. 资金与金币主线
3. 商品购买与授权主线
4. 会员订阅与下载风控主线

核心一句话可以概括为：用户通过真实支付充值金币 → 使用金币购买电影或会员 → 获得播放 / 下载授权 → 在受控设备上完成内容交付



#### 4.3.2 用户域（Account）

**User（用户表）**

**表含义**
表示平台的真实用户账号，是所有业务行为的起点。

**核心关系**

- User 与 Wallet：一对一
- User 与 UserLoginDevice：一对多
- User 与 RechargeOrder：一对多
- User 与 CoinTransaction：一对多
- User 与 PurchaseOrder：一对多
- User 与 Membership：一对多

**设计说明**

- User 只负责“身份”
- 不承载金币、会员、订单等状态，避免超级表



**Wallet（钱包表）**

**表含义**
用户当前的金币余额快照。

**核心关系**

- User 与 Wallet：一对一

**设计要点**

- Wallet 只存当前余额
- 不记录历史变动
- 所有变动来源必须可追溯到 CoinTransaction

**设计目的**

- 提高读写性能
- 保证账目清晰可审计



**UserLoginDevice（登录设备表）**

**表含义**
记录用户允许登录平台的设备，用于设备风控。

**核心关系**

- User 与 UserLoginDevice：一对多
- UserLoginDevice 与 DownloadToken：一对多

**业务约束**

- 用户最多绑定固定数量设备（如 2 台）
- 下载设备必须来源于已登录设备

**设计价值**

- 登录风控
- 下载风控
- 设备级审计



#### 4.3.3 充值与金币体系（资金域）

**RechargeOrder（充值订单）**

**表含义**
用户通过真实支付渠道（微信 / 支付宝）进行的充值记录。

**核心关系**

- User 与 RechargeOrder：一对多
- RechargeOrder 与 CoinTransaction：一对多

**关键说明**

- 充值订单只负责“钱”
- 不直接修改钱包余额
- 成功后才触发金币入账



**CoinTransaction（金币流水）**

**表含义**
金币的账本表，记录每一次金币变动。

**典型来源**

- 充值成功
- 购买电影
- 会员续费

**核心关系**

- User 与 CoinTransaction：一对多
- RechargeOrder / PurchaseOrder / MembershipRenewal → CoinTransaction

**设计原则**

- Wallet 是结果
- CoinTransaction 是过程与证据



#### 4.3.4 消费订单与购买授权（交易域）

**PurchaseOrder（消费订单）**

**表含义**
用户一次金币消费行为的订单主表。

**核心关系**

- User 与 PurchaseOrder：一对多
- PurchaseOrder 与 PurchaseOrderItem：一对多
- PurchaseOrder 与 CoinTransaction：关联

**说明**

- 一次订单可以购买多部电影
- 不直接关联 Movie，避免结构僵化



**PurchaseOrderItem（订单项）**

**表含义**
订单中具体购买的电影明细。

**核心关系**

- PurchaseOrder 与 PurchaseOrderItem：一对多
- PurchaseOrderItem 与 PurchaseLicense：一对一
- PurchaseOrderItem 与 DownloadToken：一对多

**设计意义**

- 支持按“电影级别”判断退款、授权、下载



**PurchaseLicense（购买授权）**

**表含义**
用户对某一部电影的永久购买授权凭证。

**核心关系**

- PurchaseOrderItem 与 PurchaseLicense：一对一
- User 与 PurchaseLicense：一对多
- Movie 与 PurchaseLicense：一对多

**关键约束**

- user_id + movie_id 唯一

**核心原则**

是否可播放 / 下载，只看 License，不看订单



#### 4.3.5 内容域（电影）

**Movie（电影表）**

**表含义**
平台售卖的数字内容商品。

**核心关系**

- Movie 与 PurchaseOrderItem：一对多
- Movie 与 PurchaseLicense：一对多
- Movie 与 DownloadToken：一对多

**关键字段**

- access_type：
    - FREE
    - BUY_ONLY
    - BUY_OR_VIP

**职责边界**

- Movie 定规则
- User 的权限由 License / Membership 决定



#### 4.3.6 会员体系（Membership）

**Membership（会员表）**

**表含义**
用户的会员订阅实体，表示一段时间内的会员权益。

**核心关系**

- User 与 Membership：一对多
- Membership 与 MembershipRenewal：一对多
- Membership 参与播放权限判断（不参与下载）

**设计亮点**

- 支持会员历史
- 支持状态机（ACTIVE / GRACE / EXPIRED）



**MembershipRenewal（会员续费）**

**表含义**
记录每一次会员续期行为。

**核心关系**

- Membership 与 MembershipRenewal：一对多
- MembershipRenewal 与 RechargeOrder：关联
- MembershipRenewal 与 CoinTransaction：关联

**设计目的**

- 自动续费幂等
- 账务对齐
- 风险可追溯



#### 4.3.7 下载与风控体系（Download）

**DownloadToken（下载令牌）**

**表含义**
一次受控的、可过期的电影下载凭证。

**生成条件**

- 用户已购买电影
- 设备已登录并绑定
- 未超过每日次数限制

**核心关系**

- User 与 DownloadToken：一对多
- Movie 与 DownloadToken：一对多
- UserLoginDevice 与 DownloadToken：一对多

**关键规则**

- 有效期（如 5 分钟）
- 设备绑定
- 次数限制

**设计本质**

> 下载不是权限，而是一次“被允许的行为”

## 六、关键一致性设计说明

- 钱包余额变更必须：
    - 行级锁 wallet
    - 插入 coin_transaction
- 下载次数限制通过：
    - download_daily_quota 唯一键 + 行锁
- 授权发放仅在：
    - 扣币成功后写入 purchase_license



## 七、初始化与配置建议

- 初始化金币兑换比例
- 初始化下载有效期（5 分钟）
- 初始化每日下载次数（5 次）
- 初始化最大登录设备数（2 台）
