## 二、项目背景与目标

### 2.1 项目背景

随着数字内容消费形态的成熟，用户对**高质量电影内容的在线播放、数字购买、会员订阅**需求不断提升。
本项目旨在构建一个以**数字电影内容**为核心的商城系统，支持完整的付费、会员、下载与风控机制。



### 2.2 项目目标

#### 业务目标

- 构建完整的数字内容消费闭环
- 支持“免费观看+会员观看 + 单片购买下载”的混合商业模式
- 明确下载、退款、设备绑定等关键边界，降低平台风险



#### 技术目标

- 前后端分离，接口职责清晰
- 权限、状态机、资金流无歧义
- 支持真实支付、自动续费
- 可作为长期演进的数字内容平台基础



## 三、用户账户体系需求

### 3.1 用户注册与登录

#### 注册方式

- 注册方式：**手机号**
- 登录方式：**短信验证码登录**
- 不设置密码
- 注册与登录流程合并（验证码校验成功即创建/登录账号）



#### 账号规则

- 手机号在系统中唯一
- 不支持同一手机号注册多个账号



### 3.2 登录设备管理

| 项目                   | 规则                   |
| ---------------------- | ---------------------- |
| 是否限制登录设备       | 是                     |
| 最大登录设备数         | 2 台                   |
| 超出限制               | 拒绝登录，提示解绑设备 |
| 登录设备与下载设备关系 | 登录设备 ⊇ 下载设备    |

登录设备与下载设备为两个不同维度的设备管理，但下载设备必须来源于已登录设备。



## 四、商品模型与访问规则

### 4.1 商品类型

- 商品统一为 **数字电影内容**
- 不涉及实体商品与物流



### 4.2 access_type（访问类型）

电影内容字段：`access_type`

| 枚举值     | 含义                                      |
| ---------- | ----------------------------------------- |
| FREE       | 免费播放，不可下载                        |
| BUY_ONLY   | 仅购买可播放 + 下载                       |
| BUY_OR_VIP | 购买可播放 + 下载；会员可播放（不可下载） |

**约束说明**

- 不存在 `VIP_ONLY`
- access_type 为后台可配置字段



## 五、权限判定核心规则（强约束）

### 5.1 权限优先级

**购买权限 > 会员权限**



### 5.2 播放权限判定

| 用户状态                       | 是否可播放 |
| ------------------------------ | ---------- |
| 已购买                         | 是         |
| 未购买 + 有效会员 + BUY_OR_VIP | 是         |
| FREE                           | 是         |
| 其他                           | 否         |



### 5.3 下载权限判定

| 条件           | 是否可下载 |
| -------------- | ---------- |
| 已购买         | 是         |
| 会员（未购买） | 否         |
| FREE           | 否         |

会员永远不授予下载权限。



## 六、下载交付与设备绑定机制

### 6.1 下载交付方式

- 下载方式：**签名下载链接**
- 下载链接有效期：**5 分钟**
- 签名生成因素：

```
user_id + movie_id + device_id + expires_at
```



### 6.2 下载次数限制

- 每用户 / 每电影 / 每日：**最多生成 5 次下载链接**
- 次数每日自动重置



### 6.3 设备绑定规则

| 项目           | 规则              |
| -------------- | ----------------- |
| 是否绑定设备   | 是                |
| 最大绑定设备数 | 2 台              |
| 换绑频率       | 每 30 天允许 1 次 |



## 七、会员体系需求

### 7.1 会员产品

- 月卡
- 年卡



### 7.2 会员权益

- 可播放 access_type = BUY_OR_VIP 的电影
- 不授予下载权限



### 7.3 自动续费规则

- 自动续费：开启
- 续费方式：**真实支付代扣**
- 生效时间：支付成功立即生效
- 续费成功：顺延会员到期时间



### 7.4 扣款失败处理（宽限期）

- 宽限期：**24 小时**
- 宽限期内：保留会员播放权限
- 宽限期结束：会员失效



## 八、支付与资金体系需求（金币制）

### 8.1 支付模型概述

系统采用 **“充值 → 金币余额 → 消费”** 的资金内循环模型。

- 所有消费仅使用金币
- 不支持现金直接购买电影或会员
- 金币余额不足时禁止下单



### 8.2 金币体系定义

| 项目       | 规则                            |
| ---------- | ------------------------------- |
| 金币属性   | 平台虚拟资产                    |
| 是否可提现 | 否                              |
| 是否可转赠 | 否                              |
| 金币获取   | 充值获得                        |
| 兑换比例   | 后台可配置（如 1 元 = 10 金币） |



### 8.3 充值规则

- 用户通过真实支付充值金币
- 充值成功后金币立即入账
- 充值订单与消费订单严格分离



### 8.4 消费规则（强约束）

| 场景     | 规则     |
| -------- | -------- |
| 电影购买 | 扣减金币 |
| 会员开通 | 扣减金币 |
| 金币不足 | 禁止下单 |
| 混合支付 | 不支持   |



### 8.5 自动续费与金币扣减流程

```
代扣成功 → 金币充值到账 → 扣减金币 → 会员续期
```

任何会员续期行为都必须通过金币账户完成。



## 九、订单与退款规则

### 9.1 订单类型

- 充值订单
- 电影购买订单
- 会员订阅订单



### 9.2 退款规则（强约束）

- 只要生成过下载凭证，即不可退款
- 判定粒度：订单项级别

| 场景           | 是否可退款 |
| -------------- | ---------- |
| 未生成下载凭证 | 是         |
| 已生成下载凭证 | 否         |
